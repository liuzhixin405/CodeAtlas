# 真实项目审计（2026-10-16）

起因：用户说"测试写了一堆，但是拿实际项目一试，一堆问题"。四个只读审计代理用 dist 版本对照源码逐个视图挑错：CodeAtlas 自身、ccs-backend、ccs-ui（单独 / 合并后端）、reference 下 9 个公开项目。下面按**根因**合并去重（一个根因往往在多个项目里出现），每组标严重度与出处。原始报告的证据（命令、输出、源码行）在 scratchpad 的 audit-* 目录。

严重度：**A** = 结论错（会让人信错的东西）；**B** = 关键链路漏 / 明显误导；**C** = 噪声、措辞、可用性。

## 建议顺序
1. 先修 **A 类 1–6**：都是"画出来的东西是错的"，用户信了会出事（错连控制器、读写颠倒、假入口、假边、同步异步颠倒）。
2. 再修 **7、12**：每张时序图都受影响，改动集中在 FlowBuilder / MapBuilder。
3. 然后 **8、9、10、11、16**（关键链路漏）、**13、14、15**（误导）。
4. 最后 C 类。

每修一组：先在审计用的真实项目上复现、修完再对照源码逐项核对，回归脚本里加"不该出现的东西"这类反例检查（例如：ccs-ui 续接里不得有方法不一致的匹配；ccs-backend Api 容器不得出现只在 Worker 注册的常驻服务）。
