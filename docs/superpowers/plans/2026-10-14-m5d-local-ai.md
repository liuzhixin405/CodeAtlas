# M5d：本地 AI 叙述

设计依据：`docs/superpowers/specs/2026-10-14-architecture-map-design.md` §3.5、§4、§5。用户决定：本地模型 llama-server（`http://127.0.0.1:8080/v1`，`qwen3.6-27b`）；**AI 只在预设版式里选**，不自己画；叙述文字简体中文。

## 裁定
1. 端点默认值从设计稿的 11434 改为 8080（用户机器上只有 llama-server 在跑）。
2. 叙述对象三种：容器（key = 容器键）、组件（`<容器键>|<组件键>`）、入口流程（入口符号 id）。
3. 输入只给事实子图（节点 / 边 / 入口 / 热点，各带 id），入口流程另给入口方法源码 ≤ 80 行；预算约 6000 token。
4. 输出 JSON `{summary ≤120 字, keyPoints[{text, evidence[]}], risks[], layout}`；evidence 不在输入 id 集合里 → 标 `inferred`；layout 不在该粒度的预设列表里 → null；失败重试一次。
5. 缓存键 = SHA256(模型名 + 事实文本)，存 `narratives` 表（索引版本 7）；索引后不清缓存，下次请求 hash 不同才重算；队列单线程、可停可续。
6. 预设版式：容器 `columns` | `topological`；组件 `dependency-order` | `alphabetical`；流程 `first-seen` | `grouped-external`。
7. 端点不可用（`--no-ai`、连不上、服务太旧）时视图照常，叙述卡只显示原因。非回环地址时界面标"源码将发送到 X"。

## 接口契约
```
GET  /api/arch/narrative?kind=&key=            → NarrativeDto
POST /api/arch/narrate {kind, key, force?}     → 202 NarrativeDto
GET  /api/arch/narrate/status                  → NarrationStatusDto
POST /api/arch/narrate/stop | /resume          → NarrationStatusDto
```
`NarrativeDto { kind, key, status: ready|pending|running|failed|unavailable, model, generatedAt, hash, summary, keyPoints[{text, evidence[], inferred}], risks[…], layout, error }`
`NarrationStatusDto { enabled, endpoint, model, reachable, queued, running, done, failed, lastError, remoteWarning, paused }`

## 实施记录（2026-10-14）
- 超时默认 120 → 300s（实测 2.1–2.8 tok/s，单条 150–233s）。
- 自动排队只保留最近打开的一个；显式 POST 不撤。
- 叙述质量受索引质量限制：不开 Roslyn 时组件叙述复述了启发式误报边造成的环；详见 docs/acceptance.md。
