# CodeAtlas 里程碑 2a：本地服务 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供 `codeatlas serve`：一个只监听本机的 HTTP 服务，让 VS Code 扩展（2c）和面板页面（2b）能查符号、查邻居、按光标位置找符号、触发索引并轮询进度。

**Architecture:** 新项目 `CodeAtlas.Server`（类库，FrameworkReference Microsoft.AspNetCore.App）提供 `ServerHost.Build(ServerOptions)` 返回配置好的 `WebApplication`；`IndexService` 持有两个 SQLite 连接（写连接给索引器、读连接给查询，WAL 模式互不阻塞），索引在后台串行运行并暴露进度。CLI 加 `serve` 子命令，启动后向 stdout 打印 `{"port":N}`。看门狗监视 `--parent-pid`。

**Tech Stack:** ASP.NET Core 10 最小 API、System.Text.Json、xunit（真实 Kestrel 随机端口做集成测试，不用 TestServer）。

**Spec:** `docs/superpowers/specs/2026-10-13-vscode-extension-design.md` 第 2 节、第 5 节、里程碑 2a。

## Global Constraints

- 只监听 `127.0.0.1`。
- JSON 用 camelCase（System.Text.Json 默认 Web 选项）。
- 新 NuGet 依赖：无（ASP.NET Core 走 FrameworkReference）。
- 索引库文件路径默认 `<repo>/.codeatlas/index.db`，与 CLI 一致。
- 服务内查询用独立只读连接；索引用写连接；两者都是 `IndexDatabase`，各自用一个 `SemaphoreSlim(1)` 串行化。
- 内存库不能跨连接共享，所以服务和它的测试一律用文件库。

## Review Focus

1. **索引期间查询**：索引写库时 `GET /api/search` 必须仍能返回（WAL 下读不阻塞）。→ Task 2 的 `Search_WorksWhileIndexRunning`。
2. **并发触发索引**：两个 `POST /api/index` 同时到达，只能跑一个。→ Task 2 的 `Index_SecondConcurrentPost_Returns409`。
3. **绝对路径与反斜杠**：VS Code 给的是 `D:\repo\src\a.ts`，库里存的是 `src/a.ts`。→ Task 2 的 `SymbolAt_AcceptsAbsoluteWindowsPath`。
4. **光标在定义之外**：空行、import 行、文件不在索引里，都应 404 而非 500。→ Task 1 与 Task 2 的对应测试。
5. **父进程消失**：扩展崩溃后服务不能变僵尸。→ Task 3 的 `Watchdog_ExitsWhenParentGone`（用一个短命子进程模拟）。

### Task 1: `IndexReader.GetSymbolAt`

**Files:** Modify `src/CodeAtlas.Core/Storage/IndexReader.cs`；Test `tests/CodeAtlas.Core.Tests/IndexReaderTests.cs`

**Interfaces:** Produces `SymbolRecord? GetSymbolAt(long fileId, int line, int col)`：范围包含 `(line, col)`、起点最靠后的非 module 符号；无则 null。

- [ ] **Step 1: 写失败的测试**（加到 IndexReaderTests，复用 Seed：OrderService 2:1–40:2，findOrder 3:3–10:4，saveOrder 11:3–20:4）

```csharp
    [Fact]
    public void GetSymbolAt_ReturnsInnermost_OrNull()
    {
        var (db, fileA, _, a, _) = Seed();
        using (db)
        {
            var r = new IndexReader(db);
            Assert.Equal(a[2], r.GetSymbolAt(fileA, 5, 10)!.Id);   // 方法体内
            Assert.Equal(a[1], r.GetSymbolAt(fileA, 2, 7)!.Id);    // 类名上
            Assert.Equal(a[1], r.GetSymbolAt(fileA, 10, 5)!.Id);   // findOrder 结束列之后、仍在类内
            Assert.Equal(a[2], r.GetSymbolAt(fileA, 10, 4)!.Id);   // 恰好在 findOrder 结束位置
            Assert.Null(r.GetSymbolAt(fileA, 45, 1));              // 类之后的空行，只剩 module
            Assert.Null(r.GetSymbolAt(999, 1, 1));                 // 文件不存在
        }
    }
```

- [ ] **Step 2: 运行确认失败** `dotnet test tests/CodeAtlas.Core.Tests`
- [ ] **Step 3: 实现**

```csharp
    public SymbolRecord? GetSymbolAt(long fileId, int line, int col) =>
        ReadSymbols($"""
            SELECT {SymbolColumns} FROM symbols s
            WHERE s.file_id = $f AND s.kind <> 'module'
              AND (s.start_line < $l OR (s.start_line = $l AND s.start_col <= $c))
              AND (s.end_line > $l OR (s.end_line = $l AND s.end_col >= $c))
            ORDER BY s.start_line DESC, s.start_col DESC LIMIT 1
            """, ("$f", fileId), ("$l", line), ("$c", col)).FirstOrDefault();
```

- [ ] **Step 4: 运行确认通过**；**Step 5: 提交** `feat(core): GetSymbolAt`
