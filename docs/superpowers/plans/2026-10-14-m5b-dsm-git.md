# CodeAtlas 里程碑 5b：容器内组件 DSM + git 行为叠加 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 双击容器图里的一个容器，看到它内部组件的依赖结构矩阵（DSM）：行依赖列，排成下三角，环依赖标红；叠加 git 热点与"常一起改却没有静态边"的隐性耦合。再双击一行钻到下一层（项目 → 命名空间 → 子命名空间）。

**Architecture:** Server 新增 `DsmBuilder.Build(symbols, edges, container, root, git)`（纯函数，与 `MapBuilder` 同一份输入，复用它的分组键 / ChildKey），输出组件（已排序）、矩阵单元格、强连通分量、叠加数据。Core 新增 `GitHistory`（解析 `git log --all --numstat` 的纯函数 + 子进程运行）与 `GitStorage`（`git_file_stats` / `git_coupling` 表，索引版本 5）；索引结束时与容器图一起跑。Server `GET /api/arch/dsm?container=&root=`；页面新视图 `dsmView.ts`（HTML 表格，不用 cytoscape），容器图双击容器 → DSM，面包屑 `项目 › 容器 › 组件…`。

**Spec:** `2026-10-14-architecture-map-design.md` §3.2、§3.4、§5。

## 裁定
1. 组件层级：容器内第一层 = 成员项目（目录），钻入项目后 = 该项目主命名空间的子命名空间（脚本按目录），再往下按命名空间逐级；与命名空间地图的 `ChildKey` 规则一致。
2. 排序：Tarjan 求强连通分量，分量之间按"被依赖者在前"拓扑排序，使依赖落在对角线下方；分量内按符号数降序再按名字。多成员的分量就是环，整块标红。
3. git 粒度按文件：组件的修订数 = 成员文件修订数之和（同一提交改了组件内多个文件会重复计，文档写明）；年龄 = 最近一次提交到现在的月数；隐性耦合 = 文件对共同修订 ≥ 5 且耦合度 ≥ 30%（code-maat 默认），聚合到组件对，只显示没有静态边的那些。
4. 子目录里的独立 git 仓（mt4proxy 等）各自跑一遍 `git log`，路径加前缀。
5. NetArchTest 规则还原（5e）与 `architecture.yaml` 分层声明本里程碑不做。

## Review Focus
1. 下三角要真的下三角：没有环时所有非零格子必须在对角线以下，测试逐格断言。
2. 同一组件在两个容器里（Application 同时进 Api 与 Worker）：DSM 按容器切片，只算该容器成员的符号与边。
3. git 解析对二进制文件（`-\t-\tpath`）、重命名关闭、超过 30 个文件的提交（丢弃不算耦合但算修订）要正确。
4. 没有 git（zip 解压的目录）不报错：叠加层为空并说明。
